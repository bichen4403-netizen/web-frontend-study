## 2. 知识点与三个难点
- 这个知识点讲的是什么（一句话）：二叉搜索树是一种“左子树的结点都比根小、右子树的结点都比根大”的二叉树，插入和删除都要保持这种有序性，查找的快慢取决于树的高度。
- 三个难点：先看懂一次插入怎么走，再看删除时有序性怎么保住，最后看多次插入的顺序怎样决定整棵树的形状。

| 编号 | 难点（一句话） | 学习者卡在哪一步（具体到操作） | 为什么难（抽象不可见 / 步骤太多 / 多步耦合 / 反直觉） |
| --- | --- | --- | --- |
| 难点 1 | 插入时的比较路径：新值从根开始逐个比较，沿一条路径走到空位成为叶子 | 插入一个值时，说不出每一步在跟哪个结点比、为什么往左或往右，也不清楚什么时候停下、挂在哪个结点的哪一边 | 抽象不可见：教材只画插入后的结果，中间的比较过程看不到；不少人以为新结点会插到“数值最接近的结点旁边”，或者能插进树的中间 |
| 难点 2 | 删除有两个孩子的结点时，为什么用中序后继来替换 | 删除双孩子结点时，想不通空位为什么要由右子树的最小值来补，直接把左孩子或右孩子提上来错在哪；还常漏掉“再删除后继原来那个结点”这一步 | 反直觉 + 多步耦合：直觉是把孩子直接提上来；“复制后继的值”和“删除后继原结点”是连在一起的两步，只背规则看不出有序性为什么还在 |
| 难点 3 | 插入顺序导致树退化 | 同一组数换个顺序插入时，预测不出树会长成什么样；按从小到大的顺序插入时，想不到会变成一条链，查找要比较 n 次 | 反直觉 + 抽象不可见：只记住“查找是 O(log n)”，没意识到这依赖树高，而树高完全由插入顺序决定 |

## 3. 演示策略（三个难点分别写）
### 难点 1：插入时的比较路径
- 画面构成（有哪些图形元素）：用 SVG 画的二叉搜索树（圆形结点和连线）；当前比较结点的高亮圈；指向下一步方向的箭头；已走过路径的加粗连线；新结点将要落下的空位（虚线圆圈）；右侧的比较记录列表和状态说明栏；底部播放控件。
- 演示步骤（列出 4 步以上）：
  1. 输入要插入的值（例如 35），新值出现在树的上方，状态栏提示“从根结点开始比较”；
  2. 与根结点 50 比较：50 高亮，状态栏显示“35 < 50，往左走”，通往 30 的连线加粗并出现箭头；
  3. 与 30 比较：显示“35 > 30，往右走”，路径继续加粗；
  4. 与 40 比较：显示“35 < 40，往左走”，发现 40 的左孩子为空；
  5. 空位出现虚线圆圈，状态栏说明“左孩子为空，新结点挂在这里”；
  6. 35 落入空位成为叶子，比较记录汇总“共比较 3 次”。
- 交互类型（步进推演 / 参数探索 / 对照比较 / 操作判定 / 构建拼装）：步进推演
- 用户具体怎么操作：在输入框填一个值（或点“随机一个值”）后开始插入；用“单步前进 / 单步后退”一次走一个比较，也可以点“播放”自动走、随时“暂停”停在任一中间状态；“重置”回到插入前；可以连续插入几个值，看每个新结点都落在叶子位置。
- 可调参数（至少一个，说明它影响什么）：插入的值——决定走哪条比较路径、落在哪个空位；初始树（预设 / 随机生成）——决定路径的长短和走向；播放速度——自动播放时每一步的间隔。
- 这个难点如何在交互中被化解：把“一次插入”拆成一次一次可数的比较，每一步都看得到在跟谁比、为什么往这边走，路径变成看得见的轨迹；连续插入几次以后，学习者自己就能发现新结点总是成为叶子，不会插进树的中间。

### 难点 2：双孩子删除为何用后继替换
- 画面构成（有哪些图形元素）：SVG 二叉搜索树；被删结点的红色虚线标记；用户选中的候选结点的选中框；右侧的判定面板（“可以 / 不行”和理由）；破坏有序性的那一对结点用红色连线标出；树下方一条中序序列条（结点值从小到大排成一排）；底部播放控件。
- 演示步骤（列出 4 步以上）：
  1. 用户点选一个有两个孩子的结点作为删除对象（例如根结点 50），系统标记它，并提示“请选一个结点来顶替它的位置”；
  2. 用户在树上点一个候选结点，例如右孩子 70；
  3. 系统判定“不行”：如果 70 顶上去，右子树里剩下的 60 比 70 小，把 60 和 70 标红，中序序列条上同时显示出现了乱序；
  4. 用户改选右子树中最小的 60（中序后继），系统判定“可以”：60 是所有比 50 大的数里最小的，顶上去后左边全都更小、右边全都更大；若选左子树最大的 40（中序前驱），也判“可以”，并说明课本约定用后继；
  5. 判定通过后演示删除的第一步：把 60 的值复制到被删结点的位置；
  6. 第二步：删除 60 原来的结点——它没有左孩子，最多只有右孩子，直接由右孩子顶上（本例 60 是叶子，直接删去）；
  7. 中序序列条更新，删除前后都保持从小到大。
- 交互类型（步进推演 / 参数探索 / 对照比较 / 操作判定 / 构建拼装）：操作判定
- 用户具体怎么操作：先点要删除的双孩子结点，再在树上点自己认为应该顶替它的结点；系统判对错并解释，选错可以重选；判定正确后用播放控件（播放 / 暂停 / 单步 / 重置）一步一步看完“复制后继的值”和“删除后继原结点”两步。
- 可调参数（至少一个，说明它影响什么）：删除对象——选不同位置的双孩子结点，后继离它有远有近；初始树（预设 / 随机生成）——可以生成“后继还带着右孩子”的情形，让第二步不只是删一个叶子；演示速度。
- 这个难点如何在交互中被化解：错误的选择被当场推翻，而且具体指出是哪一对数的大小关系被破坏，比只看正确过程更能建立规则感；中序序列条把“有序性”变成一排看得见的数字，删除以后仍然从小到大，学习者就能明白为什么只有后继（或前驱）能顶替。

### 难点 3：插入顺序导致退化
- 画面构成（有哪些图形元素）：两到三栏并排的树，每栏一种颜色；每栏上方是这一栏的插入序列（数字卡片，已插入的变灰）；每栏下方显示当前树高和平均查找长度；底部一张自己用 SVG 画的树高 / 平均查找长度柱状对比图；共用的播放控件。
- 演示步骤（列出 4 步以上）：
  1. 选择结点个数（例如 7）和每一栏的插入顺序（例如升序、“中间优先”、随机）；
  2. 单步插入第 1 个数，各栏同时长出根结点；
  3. 继续单步，各栏同步插入第 k 个数，树高、平均查找长度和柱状图实时更新；
  4. 插到一半暂停对比：升序那栏已经一路向右下长成斜线，“中间优先”那栏仍然左右对称；
  5. 全部插完，柱状图对比最终结果：7 个数按升序插入树高为 7、平均查找长度为 4，按“中间优先”插入树高只有 3；
  6. 在“自定义”栏拖动数字卡片调整顺序，重新播放，尝试排出树高最小（或最大）的顺序。
- 交互类型（步进推演 / 参数探索 / 对照比较 / 操作判定 / 构建拼装）：对照比较
- 用户具体怎么操作：给每一栏选一种插入顺序，或在自定义栏里拖动卡片排顺序；然后用播放 / 暂停 / 单步 / 重置让几栏同步插入，随时停下来比较几棵树的形状和数字。
- 可调参数（至少一个，说明它影响什么）：结点个数 n（7 / 15 / 31）——影响退化后的链有多长、差距有多明显；每栏的插入顺序（升序 / 降序 / 中间优先 / 随机 / 自定义）——直接决定树的形状和树高；播放速度。
- 这个难点如何在交互中被化解：同一组数只换顺序，几棵树在同一时刻并排生长，“退化成链表”不再是书上的一句话，而是一条看得见的斜线和一组能比较的树高、查找长度；学习者自己动手排顺序，就能体会到树的形状完全由插入顺序决定。

### 三者差异
- 三个难点分别用什么交互类型：难点 1 步进推演（看清一次插入的每一次比较）；难点 2 操作判定（用户选顶替结点，系统判对错并解释）；难点 3 对照比较（几种插入顺序并排、同步生长）。
- 遮住标题，别人能否从操作方式分辨出这是三个不同的难点：能。难点 1 是一棵树配一条比较记录，用户只控制节奏，看路径一步步往下延伸；难点 2 要求用户在树上点选结点、自己做决定，画面回应的是“对 / 错”和被破坏的那一对数；难点 3 画面上同时有几棵树并排生长，用户做的是挑选、排列插入顺序，看的是形状和数字的差别。
- 三个页面之间可以复用的部分（导航 / 样式 / 播放控件）：顶部导航和首页入口；整体样式 style.css；播放控件（播放 / 暂停 / 单步前进 / 单步后退 / 重置 / 调速）；SVG 画树和结点布局的函数；读取 data/ 下 JSON 的函数。这些放在 common.js，三个难点的交互逻辑分别写在 d1.js、d2.js、d3.js，讲解文字和预设数据分别放在 data/d1.json、d2.json、d3.json。

## 6. 风险与预案
- 三个难点里我最没把握的是：难点 2 删除过程的过渡动画。后继的值“移”到被删位置、后继原结点被它的右孩子顶上时，整棵树的结点位置要重新排布，动画要连贯又不乱；其次是难点 3 结点多时，升序插入会长成很长的斜线，画面需要缩放才放得下。
- 如果某个难点做不出来，降级方案是（仍然保持三个难点，不得减为两个）：难点 2 的过渡动画做不顺，就改成每一步直接重绘整棵树，用颜色和箭头标出“值从哪来、哪个结点被删”，单步、后退和判定逻辑不变；难点 3 画面放不下，就把结点个数上限降到 15、改为两栏对照，长链部分缩放显示；难点 1 的随机生成树来不及，就先只用预设树。三个难点都保留，只简化表现方式。
