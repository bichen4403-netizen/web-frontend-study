## 3. 关键技术问题与解决过程

至少 1 条，按「问题 → 排查 → 解决 → 验证」四步写；可附关键代码片段（每段不超过 20 行）。

### 3.1 输入框为空时点「随机生成」，再单步页面报错

1. **问题**：难点 1 页面把输入框清空（或填 0、100 这类非法值）后点「随机生成」，状态栏提示“请输入 1～99 之间的整数”；接着点「下一步」，控制台报 `TypeError: Cannot read properties of undefined (reading 'x')`，树不再刷新。
2. **排查过程**：报错在 `arrowSvg()` 读 `p.x`，`p` 来自 `box.pos[state.cur]`。在控制台打印 `steps` 和 `baseValues`，发现 `steps` 还是上一棵树的步骤（`cur` 是旧树里的 50），`baseValues` 却已经换成了随机树。原因是 `setTree()` 先改了 `baseValues`，再调用 `startInsert()`，而 `startInsert()` 校验失败直接 `return`，没有重建步骤。`render()` 用新树画图、用旧步骤找结点，旧结点在新树里不存在，取不到坐标。
3. **解决方案**：把输入校验拆成 `readValue()`，`setTree()` 先校验，合法才换树；不合法就保持原来的树和步骤不动。

修改前：

```js
function setTree(values) {
  baseValues = values;
  startInsert();
}
```

修改后：

```js
function readValue() {
  let v = Number(document.getElementById('value').value);
  if (Number.isInteger(v) && v >= data.min && v <= data.max) return v;
  pause();
  document.getElementById('note').textContent = fmt(data.text.invalid, { min: data.min, max: data.max });
  return null;
}

function setTree(values) {
  if (readValue() === null) return;
  baseValues = values;
  startInsert();
}
```

4. **如何验证已解决**：按原步骤复现，不再报错，树保持原样，提示语正确；再用 40 棵随机树 × 随机插入值逐帧检查：每个比较帧恰好 1 支箭头、插入完成时恰好 1 个新结点，控制台无报错。
5. **相关提交**：`f69e65a`

### 3.2 首页按空格键，页面不能滚动，后台计时器停不下来

1. **问题**：首页按空格键，页面不往下滚；在控制台看 `timer`，它变成了数字，一直在跑。`data/d1.json` 读取失败的页面也一样。难点 2 只有 1 帧时按空格，播放按钮会闪一下“暂停”。
2. **排查过程**：`common.js` 的 `keydown` 监听在每个页面都会注册，首页没有播放器，`steps` 是空数组。`play()` 里 `cursor === steps.length - 1` 即 `0 === -1` 不成立，直接 `setInterval(next, speed)`；`next()` 里的停止条件同样永远不成立，所以永远不会 `pause()`。同时 `e.preventDefault()` 拦掉了空格默认的滚动。播放按钮在只有 1 帧时是禁用的，但键盘绕过了按钮，`play()` 自己没有判断。
3. **解决方案**：键盘监听开头判断没有步骤就直接返回，`play()` 少于 2 帧不启动。

```js
function play() {
  if (timer || steps.length < 2) return;
```

```js
document.addEventListener('keydown', function (e) {
  let tag = e.target.tagName;
  if (steps.length === 0 || tag === 'INPUT' || tag === 'SELECT') return;
```

4. **如何验证已解决**：把窗口高度调小，首页按空格能正常向下滚动，`timer` 保持 `null`；模拟 `data/d1.json` 返回 404，页面显示读取失败提示，按空格不启动计时器；难点 2 初始状态按空格，按钮仍是“播放”。
5. **相关提交**：`f69e65a`

class Player {
  constructor(el, onStep) {
    this.onStep = onStep;

    el.innerHTML = `<button data-act="reset">重置</button> …… <button data-act="next">下一步</button> ……`;

      this.buttons[button.dataset.act] = button;

    if (this.total < 2) return;
    if (this.index >= this.total - 1) this.go(0);

      this.next();

  }

- 播放控件：播放到最后自动停、播完再播放从头开始、播放中切换速度、焦点在输入框时方向键不单步、焦点在按钮上按空格不会多走一步；
- 随机：40 棵随机树 × 随机插入值逐帧检查箭头数量和新结点；
- 难点 2：点叶子、点自己、换候选、上一步撤回、换树后清空选择；难点 3：播放中换顺序、左右选同一顺序；
- 手机宽度 390px：四个页面没有横向滚动条；页面里没有重复的 id。
- 刷新后状态恢复：本迭代还没有做进度保存（排在迭代②），这一项不适用。

### 4.4 本迭代 AI 使用反思

- AI 帮助最大的环节：页面整体样式和首页（直接沿用了 AI 生成的 `style.css` 和 `index.html`）；以及找边界情况的 bug，空格键和换树报错这两个问题自己很难想到去测。
- 踩过的坑（如：生成的代码用了课内未讲的特性、命名风格与项目不一致）：
  - 第一次让 AI 按开题报告生成框架，做的并不符合想法，又让它返工了一次；
  - 返工后的版本用了 `class`、`async/await`、`Map`、解构赋值、展开运算符、模板字符串等课内没讲的写法，结构也不是老师讲的“`steps` 数组 + `cursor` + `render(state)`”框架，最后只能自己按老师的框架重写 JS；
  - 让 AI 优化时，它为了画箭头往每次 `drawTree()` 都塞了 `<marker id="arrowhead">`，导致难点 3 出现重复 id；加“随机生成”时没考虑输入框不合法的情况，引入了报错。AI 改完的代码不能直接信，要再测一遍。
- 下一迭代的调整策略：
  - 让 AI 写代码前先把老师的框架和现有 `common.js` 贴给它，明确要求沿用 `steps / cursor / render(state)`，不用 `class`、`async` 等课内没讲的写法；
  - 一次只让 AI 做一个功能点，做完马上测试、单独提交，方便对比和回退；
  - 每次 AI 改完都按 4.3 的边界清单在浏览器里过一遍再合并。
